# XTranslate 0.4.0

Windows 划词翻译工具。使用 C# / WPF：选中文字、快捷键取词、查看翻译，然后继续工作。

> 源码版本 **0.4.0**：基于 0.3.0 的多服务翻译与更新能力，加入跟随系统／浅色／深色 Fluent 外观、系统强调色、紧凑卡片布局、统一托盘菜单及取词快捷键启停，并修复不同缩放比例显示器之间切换时的窗口尺寸限制。下载与正式发布状态以 [GitHub Releases](https://github.com/wowayou/x-translate/releases) 为准；本版检查结果和未验证边界见 [0.4.0 验收记录](docs/ACCEPTANCE-0.4.0.md)，界面规范见 [设计与交互规范](docs/DESIGN-SYSTEM.md)。

## 系统要求

- Windows x64。实测平台为 Windows 11 25H2（build 26200）；Windows 10 的支持边界见下。ARM64 设备的系统 x64 仿真未单独测试。普通用户权限即可，无需管理员。
- 便携版不需要安装任何运行时；轻量版需要 .NET 10 桌面运行时。不知道选哪个就用便携版。
- 运行时为 .NET 10（长期支持版，微软支持到 2028-11-14）。微软的 [.NET 10 正式支持清单](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md) 中，Windows 10 仅含 LTSC 等长期服务版；普通 Windows 10 22H2 已于 2025-10 结束支持，不在官方保证范围内。本版未在 Windows 10、ARM64 或远程桌面中实测，不把 Win11 上的模拟降级测试称为这些平台已通过验收。

## 开始使用

1. 解压整个发布包到可写目录，运行 `XTranslate.exe`。不要只移动 EXE。
2. 默认选择 **Google · 非官方网页接口**，无需填写 API 密钥；需要能访问 Google 的网络。
3. 在输入框粘贴文字，点击「翻译」或按 **Ctrl+Enter**。原文将发送给当前选择的服务。
4. 在其他应用选中文字，按 **Ctrl+Q**（可在设置中自定义）。首次默认只取词，按 Enter 翻译；可在设置中开启「取词后自动翻译」。
5. **Esc** 或关闭窗口会收起到托盘。双击托盘打开，右键托盘可彻底退出。

界面语言可在主窗口右下角或设置里切换：跟随系统 / 简体中文 / English。切换只改变界面文字，不影响原文、译文、目标语言或翻译服务，也不会触发新的请求。原文区提供「粘贴」「清空」按钮；「置顶」可让窗口保持在前并阻止取词弹窗因失焦自动收起。键盘：Ctrl+Enter 翻译、Ctrl+L 聚焦原文、Ctrl+Shift+C 复制译文、Esc 收起；粘贴/清空也可通过原文区按钮完成。

取词快捷键可在设置中录制：Ctrl 或 Alt 加字母、数字或 F1–F11（F12 为系统保留）。新组合注册失败时保留原快捷键并提示；默认 Ctrl+Q 被占用时，本次运行尝试 Ctrl+Alt+Q。设置及托盘菜单均可暂停／恢复取词快捷键；关闭时释放注册，不影响手动翻译。再次运行 EXE 会唤出已有窗口。

主窗标题操作与底部状态／界面语言固定；普通默认窗口不显示多余整页滚动条，长原文／译文各自滚动。小窗口或学习详情放不下时只滚动中间正文，滚动条不遮挡标题和卡片操作。

外观在「设置 → 通用」选择跟随系统／浅色／深色，即时预览，取消还原，保存后持久化；切换不清空文本、不重发请求。强调色跟随 Windows，高对比度优先。支持时使用 Windows 11 的 Mica（云母）背景材质，不是全透明亚克力；旧系统、远程会话或关闭背景材质时保留实色可读界面。保留系统标题栏、缩放与贴靠，不做鼠标点击穿透。

### 便携版与轻量版

两种包都是解压即用的绿色版：无安装程序，程序不写注册表，配置与日志只在 EXE 旁的 `data/`。删除文件夹即可完全移除。

| 包 | 内容 | 需要 |
| --- | --- | --- |
| `XTranslate-<版本>-win-x64-portable` | 单个 EXE + WPF／SQLite 原生 DLL 与许可文件，内置 .NET 运行时；压缩包体积见发布页 | 无 |
| `XTranslate-<版本>-win-x64-lite` | 不含运行时的轻量包；压缩包体积见发布页 | 已安装 [.NET 10 Desktop Runtime x64](https://dotnet.microsoft.com/download/dotnet/10.0) |

两种形式的实测数据见 `docs/PERFORMANCE.md`。便携版不使用单文件压缩（实测使私有内存约翻倍），也不把原生库解压到 `%TEMP%`。Windows 资源管理器会像对待任何被运行过的程序一样，在 `MuiCache` 中记录 EXE 显示名，托盘区也会记住图标；这些由系统写入，不属于程序配置。放在只读目录（如受保护的 Program Files）时设置无法保存，程序会提示而不会改写到其他位置。0.2.1 已发布包仍是旧的 `standalone` 目录格式；0.3.0 起使用上述两种包。

## 已实现

- 全局快捷键、UI Automation 选区读取、保守的模拟复制取词。
- 跟随系统／浅色／深色主题、系统强调色、原生窗口框架、置顶开关、分区设置与一致的托盘菜单。
- 简体中文 / English 界面切换（可跟随系统），独立于翻译目标语言，切换立即生效并持久化。
- 取词弹窗失焦自动收起（可在设置关闭），窗口置顶时保持可见；下拉选择与进入设置不会误收起。
- 可编辑原文、自动识别源语言、33 种目标语言（含西班牙语、意大利语、荷兰语、印地语、泰语、繁体中文等）、复制译文。服务未映射的语言在下拉中禁用，不会发出请求或替换为别的语言。
- Google 非官方网页接口；DeepL 官方 API Free / Pro；可添加多个 AI 服务，原生支持 OpenAI 兼容 Chat Completions、Anthropic Messages、Google Gemini generateContent 三种协议，每个服务单独保存地址、模型、密钥和流式选项。
- Microsoft Translator 与 Papago 已保留稳定 provider ID 和禁用界面入口，尚未接入真实 API，不会被误选或发出请求。
- 明确来源、模型（AI）、耗时；20 秒请求超时；取消与重试。失败时显示错误分类、HTTP 状态码和请求编号，便于对照日志，不显示密钥或远端返回正文。
- 编辑原文、切换服务、关闭弹窗会取消旧请求，迟到结果不会覆盖新结果。
- 失败时默认不换服务；可在设置中开启「失败时自动换服务」，按你排好的顺序改用备用服务（见下）。
- 密钥由 Windows DPAPI 按当前用户加密保存。诊断日志不包含原文、译文或密钥。
- 按当前显示器工作区定位弹窗，声明 Per-Monitor V2 DPI awareness。

每次翻译最多 3000 字符。没有并行比较、译文质量评估、历史记录、无人值守自动安装更新和开机启动；手动应用内更新及可选的每日检查已支持。工作区新增可选的 AI 原文学习检查及现截图 OCR 翻译（均未发布），见下方说明；它们不等于译文质量认证。

## 学习：先检查原文，再看译文

主窗勾选「学习：检查原文（本次会话）」，主动选好 AI 服务后，点击「检查并翻译」或 Ctrl+Enter。检查区区分语法／拼写观察、用法建议、语域说明及歧义，显示建议最小修正和本次翻译的理解依据；**原文输入框保持不变**。意思不确定时提示澄清，不提供确定译文或启用整份译文复制。

- 开关重启默认关闭；勾选、编辑、切换服务或界面语言不发请求。开启时，快捷键取词后的自动翻译也会暂停，等待手动确认。
- 只使用当前 AI，最多一次请求完成检查＋翻译；不自动换服务，不展示半份流式检查，也不修改保存的流式偏好。Google／DeepL 明确提示不支持检查，不偷偷改用 AI。
- 更长的提示词和输出可能增加 token 费用，一次请求不等于固定费用。检查可能误报或漏报，不是权威语法认证或事实核查；「未发现明显问题」不代表原文完全正确。普通翻译明确标为「原文未检查」。
- 检查结果不自动保存为学习历史。工作区已实现 L1 本地学习本（未发布）：原文区星标主动收藏词／短语／句型，确认答案及可选语境；标题栏学习本入口可编辑／删除、备份恢复和先回想再揭示、自评安排间隔复习。选中局部词语不会预填整段译文作为释义；数据和备份为明文，学习本全程不发网络请求，也不强制影响翻译术语。实际检查与边界见 [L1 验收记录](docs/ACCEPTANCE-LEARNING-L1.md)，后续 L2／L3 分期见 [语言学习计划](docs/LEARNING-PLAN.md)。本步未调用真实付费服务验证语言判断。

## 现截图、现翻译与原文对照（工作区，未发布）

点主窗标题区的截图 OCR 图标，选择**本机已安装的识别语言**、翻译服务和目标语言，点击「框选并翻译」并在当前显示器拖动选区。无需先保存截图／打开图片；框选结束后本地识别并向所选服务发送一次识别文字。打开窗口、切换语言／服务或勾选开关本身不读取屏幕或发翻译请求。

- 同一窗口左侧保留原始截图和可编辑识别文字，右侧显示译文。OCR 可能误识别／漏字或打乱排版，原图及引擎空格／换行保持原样；修改识别文字后旧译文失效，再点「翻译识别原文」。原文／译文各自滚动，小窗口页面可滚动且底部按钮固定，不叠加左栏整块滚动；切换界面语言也更新“原文未检查”来源说明，不重发请求。不把译文覆盖回图片或源应用，也不把没有原文检查的结果当作语法正确。
- 「截图后立即翻译」在本次会话勾选，点击框选按钮才授权一次所选服务请求；可关闭后只做本地识别，再核对原文手动翻译。请求接收主机始终显示；不使用普通自动回退／重试、不上传图像。AI 可能计费，一次请求不是金额硬上限，取消不保证服务端立即停止计费。
- 截图只留内存，不写图片／历史／日志；Escape／失焦取消，未框选不识别／翻译。识别／翻译失败保留图片／原文，不展示迟到结果。一次仅当前显示器、不跨屏；尺寸最多 8192、像素最多 800 万；识别输出最多 20000 字符，翻译及导入主窗最多 3000 字符。可另打开本地静态 PNG（最多 16 MiB／4096 个块），解码前验证块校验和与关键顺序，损坏／动画文件明确拒绝，不支持其它格式或隐式网络／剪贴板读取。
- 应用排除在读屏前检查所有与选区相交的可见窗口，包括被遮挡的排除应用，可能保守误拒绝；窗口变化／未知归属明确失败。**这不是系统隐私隔离**：窗口透明、圆角及阴影也可能包含背景像素，枚举与捕获不构成原子桌面快照，需主动避开敏感内容。

当前没有独立全局截图热键。两种隔离发布包和有限复杂生成图已阶段验收，但双栏误字、表格漏项／错序仍如实保留；不保证复杂版面准确。`2f18c85` 两包通过减少像素重复分配后的有界 OCR 资源短测，旧超限证据仍保留；后续主窗滚动布局修复的两包已通过功能阶段验收及各两批60秒OCR资源短测，均满足原门限；首个旧Lite预热的采样覆盖失败保留且未重跑；续测已完成原计划剩余3次预热及12次正式进程，正式样本全部通过严格采样验收，但Portable开合p95及两版启动中位数上升，仍未签收性能无回退（见[本次对照](docs/PERFORMANCE.md#2026-10-25-主窗布局包三轮续测仍未签收无回退)）。后续[分段定位](docs/PERFORMANCE.md#2026-10-26-启动与-portable-开合分段定位非发布验收)将启动差异缩小到Loaded前、隔离稳态开合差异指向同步Hide；[原材质单因素对照](docs/PERFORMANCE.md#2026-10-26-fluent-材质单因素对照因预等待边界停止)确认开关生效，但矩阵因诊断预等待不足5秒停止，失败未补跑／改判；随后[预等待修复与独立三轮对照](docs/PERFORMANCE.md#2026-10-26-诊断预等待修复与独立三轮材质对照)的新诊断协议16/16通过，但两版完整开合p95仍方向不一致，不能认定关闭材质是充分修复；产品默认不变，发布仍阻塞。`2f18c85` 对 `v0.3.0` 的三轮发布性能已测，但离屏开合延迟与 Portable 私有提交内存有所上升，尚未签收性能无回退（见[性能记录](docs/PERFORMANCE.md#2026-10-23-最终-ocr-候选与-v030-三轮对照未签收性能无回退)）。短测不保证长期余量，真实收费接口、多应用／跨 DPI 多屏和长时负载仍未闭环。已运行的本地引擎、受控真实框选／读屏、对照界面及模拟翻译证据见 [Q3 阶段验收](docs/ACCEPTANCE-OCR-Q3.md)，固定生成图的重放方法见 [OCR 验收工具](tools/ocr/README.md)。

## 服务配置

Google 的接口非官方，可能限流、失效或被所在网络阻断；界面会明确显示错误，不保证长期可用。

DeepL：填写自己的 API key，根据账户类型选择 Free 或 Pro。首版仅允许官方接口。

AI 翻译服务：在「设置 → AI 翻译服务」中「添加服务…」，从 OpenAI、DeepSeek、Anthropic Claude、Google Gemini 模板或「自定义 OpenAI 兼容服务」创建，然后填写自己的 API key。每个服务都会出现在主界面「翻译服务」下拉中；选中哪个就只发给哪个，失败不切换到其他服务。模板不附带任何密钥，默认模型名是 2026-10 查阅官方文档时的轻量模型，只是可编辑初始值，需要与你的账户权限匹配。

| 协议 | 填写 | 最终地址 | 鉴权 |
| --- | --- | --- | --- |
| OpenAI 兼容 | 主机、`…/v1` 或完整路径 | 主机补 `/v1/chat/completions`（DeepSeek 补 `/chat/completions`）；`/v1` 补 `/chat/completions`；其他完整路径原样使用 | `Authorization: Bearer` |
| Anthropic Messages | 主机或前缀（如 `https://api.deepseek.com/anthropic`） | 补为 `…/v1/messages` | `x-api-key` + `anthropic-version: 2023-06-01` |
| Google Gemini | 基础地址，模型名单独填写 | `…/v1beta/models/{模型}:generateContent`，流式为 `:streamGenerateContent?alt=sse` | `x-goog-api-key` 请求头，密钥不进网址 |

地址与所选协议明显不符（例如 OpenAI 兼容协议填了 `/v1/messages`）会在保存前提示。修改地址到另一个主机时会清空该服务的密钥，需重新填写，避免把密钥发给别的服务；不同服务的密钥互不复用。删除服务会同时删除它保存的密钥。第三方兼容服务会显示其主机名，不能误认为由原厂提供。自动测试不调用真实付费服务。

旧版本的单个 AI 配置在首次启动时自动迁移为一个命名服务（例如「DeepSeek」），密钥随之迁移，无需重新填写。

三种协议直接基于 .NET 自带的 HTTP 实现，未引入官方 SDK：三个官方 SDK 会额外带来 26 个 DLL（约 22 MB），且默认自动重试、需要逐一关闭；本应用单个服务每次只发一次请求，自行处理流式与错误边界；普通翻译的可选回退仍按下述上限执行。

### AI 流式输出

在「设置 → AI 翻译服务」中为某个服务勾选「AI 流式输出（边生成边显示）」，保存后选择 AI 服务并翻译。默认关闭，旧配置无需迁移；Google 和 DeepL 的行为不受影响。

- 使用同一次请求的增量内容显示预览，不播放人为延迟的逐字动画；界面约每 50ms 合并更新一次。
- 生成中标记「尚未完成」，显示实际接口主机和模型；完整结束后才启用「复制译文」与 Ctrl+Shift+C。仍可手动选择局部文本复制。
- 取消、编辑/清空原文、切换服务或目标语言、进入设置、收起窗口都会取消请求并清除未完成内容；迟到分段不会覆盖新请求。切换界面语言不会中断请求或重新发送。
- 20 秒超时覆盖整个生成过程。连接中断、输出截断、拒绝或协议错误都不当作成功译文；同一服务不会自动重试或降级；只有开启「失败时自动换服务」才会改用备用服务，并先清除未完成内容。
- 服务必须支持对应协议的标准流式输出（OpenAI 兼容需返回 `[DONE]`，Anthropic 需返回 `message_stop`，Gemini 需以 `finishReason: STOP` 结束）。若提示不支持，可自行关闭该选项后手动重试。取消不保证服务端立即停止生成或计费，具体取决于所用服务。

### 失败时自动换服务（默认关闭）

在「设置 → 失败时换服务」开启后，普通翻译按以下规则执行；**原文学习检查不使用自动回退**：

- **顺序**：总是先用主界面所选服务；失败后按设置中的列表从上到下尝试勾选的服务（列表可上移/下移、取消勾选）。新添加的 AI 服务默认出现在列表末尾并勾选。
- **触发**：超时、网络错误、限流（含本地限流保护期）、服务端错误、密钥无效或无权限、回答不完整/被截断/被拒绝。
- **不触发**：原文为空或超长、你手动取消、编辑原文或切换服务。
- **跳过而不发请求**：未设置密钥、模型或地址无效、不支持当前目标语言的服务。
- **上限**：每次翻译最多实际发出 3 次请求。
- **透明**：开启后，翻译按钮旁会列出原文可能依次发送到的所有服务；成功时状态栏写明由哪个服务完成、之前谁因何失败，来源行标注「自动换服务」；全部失败时逐一列出原因。日志按次记录每个服务的结果，不含原文和地址。
- **隐私**：开启即表示同意在失败时把原文发给列表中勾选的其他服务；不想发给某个服务就取消勾选。

## 取词边界

### 鼠标划词图标（工作区，未发布）

在「设置 → 通用」开启「显示鼠标划词图标」（默认关闭），可从托盘暂停／恢复。主窗隐藏且空闲时，鼠标拖选／双击会触发本地 UI Automation 选区确认（含短暂读取所选正文，最多 3000 字符），不模拟复制、不碰剪贴板、不联网；无可用选区、密码框、应用排除或窗口变化不显示图标。图标不抢焦点，5 秒后失效，点击会再次检查原窗口／选区再导入主窗，**不受快捷键自动翻译设置影响，始终等你核对后手动翻译**。

新选择、外部点击／滚动、Escape、前台窗口变化、打开设置／学习本或主窗、停用和退出会撤销图标与迟到结果。主窗已显示或忙碌时不自动取词，避免覆写草稿；不支持的应用可用快捷键或手动粘贴。Win32 钩子可能被系统静默移除，不能保证一直有效；不响应时主动启停，不自动反复注册。实际本地验收、资源边界和尚未覆盖的第三方完整鼠标／跨 DPI 链路见 [Q2 验收记录](docs/ACCEPTANCE-MOUSE-Q2.md)。

### 应用排除与快捷键兼容捕获

工作区新增「设置 → 通用 → 不取词的应用」（未发布）：每行一个进程文件名，如 `chrome.exe`、`Code.exe`，最多 128 项；精确、不区分大小写，同名程序都被排除，不支持路径或通配符。排除应用按取词快捷键时，在读取选区／剪贴板之前停止，不弹窗、不发送请求，也不改动已有手动输入或取消先前请求；手动粘贴翻译仍可使用。非空名单但无法识别应用时也拒绝取词。非法规则或无法解析的配置不会静默变成空名单：暂停取词，原文件不改写，需在设置明确修正／清空后保存。全局快捷键仍占用，不能保证把按键透传回应用；这不是系统级防泄露隔离。实现与 QTranslate 后续鼠标图标／本地 OCR 的边界见 [交互参考](docs/INTERACTION-REFERENCES.md)。

优先使用 UI Automation，是否可用取决于目标应用。兼容取词会模拟 Ctrl+C，暂时改变剪贴板；只在可备份的文本、HTML、RTF 等格式上尝试，读取后恢复。如果有其他应用更新剪贴板，会放弃恢复以避免覆盖新内容。

图片、文件、特殊格式或大剪贴板会阻止兼容取词。已知终端和带内嵌终端的开发工具不会使用模拟 Ctrl+C，以免中断命令；仍可尝试 UI Automation 或手动粘贴。普通权限不能保证读取管理员运行的软件。无选区、慢响应、远程桌面、剪贴板管理器和自定义控件仍需实测；兼容取词无法保证不被系统剪贴板历史或第三方剪贴板管理器观察到。

## 版本与更新

版本号遵循 `主.次.修订`，只有一处来源：`src/XTranslate.App/XTranslate.App.csproj` 的 `<Version>`；EXE 文件版本、「设置 → 关于与更新」和发布包名称都取自它。

更新只替换程序文件，`data/`（设置、加密密钥、日志）原样保留：

- **从文件更新**（始终可用）：下载发布包 `XTranslate-<版本>-win-x64-portable.zip`（轻量版为 `-lite.zip`），在「关于与更新」点「从文件更新…」。同目录有 `build.ps1` 生成的同名 `.sha256` 文件时先校验摘要；没有时会先提示，仍会检查包结构、版本类型（便携/轻量须一致）和版本号（必须更新）。
- **在线检查**：点「检查更新」或开启「每天自动检查一次」（默认关闭）。会访问 `api.github.com`，对方可看到 IP 和当前版本号，不发送原文、配置或密钥。只接受正式版（不含预发布），只从 GitHub 的 HTTPS 地址下载，必须与发布页公布的 SHA-256 一致。仓库无法访问（如改为私有）时会明确提示，可改用「从文件更新」。
- **安装过程（工作区修复）**：校验并解压到程序目录内的唯一暂存目录，记录每个程序文件摘要，准备阶段不替换正在运行的 EXE／DLL。点「立即重启」（设置页先保存有效修改），或从托盘正常退出，才启动经再次核验的暂存更新进程；它确认旧 PID／启动时间、正常 exit 0 和互斥锁后，复制独立 payload、逐文件改名 `*.old` 并替换，失败回滚。更新程序自己的运行路径始终不动；需要重启时新应用等它退出后启动并清理残留。
- 关闭设置会取消尚在准备的包；一次只能准备一个更新。更新程序启动失败会撤销本次计划，保留旧应用和错误提示，允许正常退出，不隐式重试。崩溃／强制终止或回滚不完整不会称作成功，保留恢复证据；具体恢复方法和 **0.3.0 旧版迁移限制**见 [更新验收与恢复说明](tools/update-e2e/README.md#失败恢复与旧版迁移)。这些修复不会追溯改变已发布旧包。
- 安装前还会检查：程序文件夹是否可写（放在 Program Files 等受保护位置时直接提示，不下载）；轻量版的新版本若需要本机没有的 .NET 运行时会拒绝安装，避免更新后无法启动。
- 开发构建（`src/.../bin/`）不会自我更新，用 `install.ps1` 更新本机副本。
- 发布：`./build.ps1` 与 `./build.ps1 -Flavor Lite` 生成 ZIP 和 `.sha256`，上传到同一个 `v<版本>` Release（GitHub 会为每个附件显示 SHA-256 摘要，应用读取的就是它）。

## 数据与隐私

配置与日志位于 EXE 旁的 `data/`。`settings.json` 中 API key 字段为空，凭据以 DPAPI 密文保存；便携文件夹带到另一台电脑或换 Windows 用户后，旧密钥无法解密，程序会提示重新填写，其余设置照常保留。DPAPI 防不住同一 Windows 用户下运行的恶意程序。不要将 `data/` 随发布包分享。

日志只包含请求 ID、服务类型、耗时、状态、错误分类和 HTTP 状态码，不含地址、原文、译文或密钥；最多保留当前与上一份约 1 MB 日志。没有默认翻译历史。选区本地读取；点击翻译、主动开启快捷键自动翻译或执行「框选并翻译」，才会发送原文／识别文字到所选服务，截图像素不上传。

## 构建与验证

要求 Windows 与 .NET 10 SDK（`global.json` 固定主版本，允许更新的 10.0 功能版本）。Core 没有额外 NuGet 库依赖；App 与文件存储测试使用 `Microsoft.Data.Sqlite 10.0.13` 及其 SQLite 传递依赖（D1.2 磁盘索引）。本地 OCR 适配项目以 `Microsoft.Windows.CsWinRT 2.3.1` 及固定 Windows SDK 元数据生成有限投影，发布需保留 `WinRT.Runtime.dll` 及第三方许可，不携带完整 Windows API 投影 DLL；生成器只在构建时使用。仓库 `.tools/dotnet/` 中存在 SDK 时脚本优先使用，否则使用 PATH 中的 `dotnet`；验收脚本会让依赖运行时的测试构建使用同一套运行时（设置 `DOTNET_ROOT`）。

```powershell
./install.ps1               # 从源码安装/更新本机使用的便携版（默认 artifacts/XTranslate），见下
./build.ps1                 # 运行核心测试并生成带版本号的发布包（便携版，内置运行时，首次需要下载运行时包）
./build.ps1 -Flavor Lite    # 生成轻量版（需目标机器已装 .NET 10 Desktop Runtime）
./verify.ps1               # 核心测试 + 真实 WPF 生命周期验收（模拟 HTTP）
./verify.ps1 -LiveGoogle -NativeChecks
pwsh tools/update-e2e/Run-UpdateE2E.ps1   # 真实二进制的原地更新端到端测试（临时目录，不联网）
./benchmark.ps1            # 本地 UI 性能基准（1000 次弹窗 + 200 次 mock 翻译 + idle 三阶段）
./memory-soak.ps1           # 默认 8 小时本地稳定性测试（离线构建；无网络/剪贴板/用户数据）
# -Ocr 显式增加生成图真实本地 OCR／模拟翻译；-ExecutablePath 测指定包，Lite 同时加 -FrameworkDependent
```

长测参数、离线缓存要求及已测边界见[内存诊断说明](docs/MEMORY-DIAGNOSTICS.md#ocr-workload-and-supplied-packages)；短测通过不等于本版八小时验收。

`-LiveGoogle` 只向 Google 发送固定测试句；`-NativeChecks` 会创建固定文本测试窗口，验证真实 UI Automation 选区读取、快捷键注册和当前显示器内的定位，不读取用户剪贴板。Windows 不允许后台测试窗口获取前台焦点时，测试会改为读取明确指定的本程序测试控件，并在报告中注明：完整前台快捷键链路仍需手动验证。

真实 AI 服务自检（会产生一次计费请求，需你主动执行）：`XTranslate.exe --live-ai-check <data 目录> <报告.json> [服务名]`。只读配置，默认测当前选中的 AI 服务，按当前流式设置发送固定句 `Hello, world.` 一次；不打开窗口、不注册快捷键、不写日志；报告只含最终地址、模型、错误分类/状态码、耗时和固定句译文，不含密钥。建议先把 `settings.json` 复制到临时目录再指向它，用完删除。

`install.ps1` 一条命令完成本机更新：先发布到目标旁的临时目录并运行核心测试与 WPF 验收（`-SkipTests` 可跳过），通过后才动已安装的副本；若该副本正在运行，通过 `XTranslate.exe --exit` 请求它按托盘「退出」的正常流程关闭（设置窗口打开时不会关闭，脚本停止且不做改动），从不强制结束进程，也不关闭从其他目录运行的实例。随后旧程序改名为 `<目标>.previous`（只保留一份、不含数据，可用于回退），原 `data/` 原样移入新目录；首次安装时若源码 Release 构建下已有 `data/settings.json` 会复制过来。之前在运行则自动重启（或加 `-Launch`）。可用 `-Target` 指定其他目录、`-Flavor Lite` 安装轻量版。不写注册表、不创建快捷方式。

`build.ps1` 先发布到一次性隔离 staging，再从该目录生成压缩包，避免把旧日志、截图或用户数据带入包内；若目标版本目录或 ZIP 已存在，脚本会停止并要求手动移走旧产物，不会删除或覆盖它们。`verify.ps1` 每次使用唯一 run 目录并确认本次进程实际写出了报告；应用的 smoke 模式在报告目录下再创建本轮专用 `smoke-data-<随机 ID>`，不继承 EXE 旁旧模拟设置，失败／超时后的数据保留作证据而不影响下轮。

验收 JSON 和界面 PNG 写入 `artifacts/verification/`；本版结果与边界以 `docs/ACCEPTANCE-0.4.0.md` 为准，旧版本与最初流式功能的记录保留作历史证据。截图阶段的进程内存包含渲染与测试开销，不是空闲内存基准。`benchmark.ps1` 的性能模式包含 1000 次离屏弹窗 Show/Hide、200 次本地固定 mock 翻译，以及启动/可见 idle/隐藏 idle/恢复 idle 资源阶段；它排除真实网络耗时，网络延迟不得混为 UI 性能。性能方法与结果说明见 `docs/PERFORMANCE.md`，本 README 不对未记录的性能指标作达标结论。

应用图标为原创生成的位图（见 `docs/ICON.md`）。`tools/icon-builder/Build-Icon.ps1`（Windows/System.Drawing）只做技术性缩放与打包，生成 `src/XTranslate.App/Assets/xtranslate.png` 与 `src/XTranslate.App/Assets/xtranslate.ico`；验证时请把输出指向独立目录，避免覆盖 shipping assets。

应用默认使用 WPF 软件渲染。当前界面以文本和静态控件为主；本机受控验收中，该策略显著降低隐藏状态的私有驻留内存，并未降低离屏 Show/Hide 或本地翻译基准。该结果不等同于所有显卡、DPI 和远程桌面环境的通用性能保证。

## 代码结构

`src/XTranslate.Core`：服务适配、错误处理、结果来源，以及 `Lexicons/` 下的词典／术语导入校验、匹配与数据导出核心；不依赖 WPF。

`src/XTranslate.App`：窗口、托盘、快捷键、取词、设置与诊断。

`src/XTranslate.Ocr.Windows`：按需 Windows 本地 OCR，生成有限 C#/WinRT 投影，不依赖 WPF；`tests/XTranslate.Ocr.Tests` 为模拟边界及可选真实本地引擎样本。

`tests/XTranslate.Core.Tests`：无第三方测试框架的可执行测试集。

`tools/performance`、`tests/XTranslate.PerformanceTools.Tests`：隔离探针预等待保障、已验收报告的只读尾部分解及工具回归（尾部分解另有 `tests/performance_popup_tails_tests.py`），不编入产品、不代表性能签收；契约及显式测试模式见[工具说明](tools/performance/README.md)。

本版本独立实现，没有复制报告中其他翻译器的源码或品牌素材。
