## 前置修复：窗口验收数据隔离

核心切片新增后 Core 141/141、构建零警告；首次 WPF 重跑超出原有 45s 上限（`stage1-final.log`、`stage1-ui/`），下一次则在“失败不换服务”断言失败（`stage1-recheck.log`）。核对发现 smoke 模式复用了 EXE 旁 `smoke-data`：超时中断留下 `AutoFallback=true` 等模拟偏好，污染下一次运行；首轮模态停滞的直接原因未确证，不将它归结为手势代码。

修复仅作用于 smoke 模式：每次启动在报告目录下创建独立 `smoke-data-<GUID>`，不删除旧数据或修改正常应用存储。保留旧脏数据的情况下，同一二进制两轮分别 **141/141 Core、81/81 WPF**（`isolated-check.log`／`isolated-repeat.log`、`isolated-ui/run-20261021-003716-6e745613/` 和 `run-20261021-003739-c4a94e86/`），每轮各有独立设置目录；未提高超时或放宽旧断言。该修复不证明桌面焦点／模态操作永不受环境影响。

## 有限规格与关键取舍

- 独立开关，首次／旧配置默认关闭；设置保存后生效，可从托盘暂停／恢复。关闭时不注册鼠标或前台窗口事件钩子，不扫描选区。无后台 HTTP、自动翻译、语言包下载、输入模拟或剪贴板操作。
- 为避免将窗口拖动误判为划词，启用后在真实拖选或双击结束时做本地 UI Automation 选区探测：只读候选窗口内的文本选区及边界，确认手势端点位于选区附近，拒绝密码框、空／退化选区、超限、窗口变化和未知身份。**探测包含短暂读取所选正文**，不是“点图标前完全不读文字”；设置必须明确告知。没有可用 UIA 就不显示图标，不偷偷模拟 Ctrl+C。
- 复用 Q1 应用排除，在 UIA 前判断；配置无效也暂停鼠标功能。应用排除仍是便利过滤，不是系统防泄露沙箱，不按浏览器网址区分。
- 图标不激活目标外的窗口、不显示正文、最多保留 5 秒。新选择、外部点击／滚动、Escape、前台变化、进入设置／学习本、主窗操作、停用或退出都撤销候选。点击时再次核对窗口、规则、选区内容和有效代次，再将原文填入主窗，**无论快捷键自动翻译设置为何都不自动发送**。
- 不覆盖正在进行的翻译、取词或模态编辑。主窗已显示时不提供自动鼠标图标，以免替换已有草稿；快捷键／手动粘贴继续可用。主题和界面语言只更改本地标签，不重新读取正文或请求翻译。
- 全局低级鼠标钩子回调仅筛选按钮／滚轮事件、快照坐标和窗口标识并有界排队；移动事件不发工作、不读取进程名／正文／文件。忽略并撤销注入事件。UIA 在后台执行，与快捷键共用单工作者占用保护；超时不生成无界线程或自动重试。前台事件只用于撤销；定时检查只在候选处理中或图标可见时运行。

## 分阶段交付与检查

1. 纯手势／几何规则：固定输入覆盖拖选、双击、注入、窗口／时钟变化、负坐标、极端坐标及边界拒绝；独立本地提交，不宣称已有 UI。
2. Windows 适配、图标与主窗设置／托盘接入：真实 WPF 交互、固定 OS／UIA 边界替身、取消与迟到结果、开关保存／失败回滚、定时器／钩子生命周期、中文浅色／英文深色及缩放定位；保留核心、存储、诊断及旧 WPF 回归。
3. 单独记录实际使用的原生边界和未覆盖项。受控 UIA 样本不是第三方软件的完整运行对照；模拟钩子不是实际全局钩子验证。是否具备真实边界证据决定相应声明，不能靠测试数量替代。
