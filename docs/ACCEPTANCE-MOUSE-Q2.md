## 有限规格与关键取舍

- 独立开关，首次／旧配置默认关闭；设置保存后生效，可从托盘暂停／恢复。关闭时不注册鼠标或前台窗口事件钩子，不扫描选区。无后台 HTTP、自动翻译、语言包下载、输入模拟或剪贴板操作。
- 为避免将窗口拖动误判为划词，启用后在真实拖选或双击结束时做本地 UI Automation 选区探测：只读候选窗口内的文本选区及边界，确认手势端点位于选区附近，拒绝密码框、空／退化选区、超限、窗口变化和未知身份。**探测包含短暂读取所选正文**，不是“点图标前完全不读文字”；设置必须明确告知。没有可用 UIA 就不显示图标，不偷偷模拟 Ctrl+C。
- 复用 Q1 应用排除，在 UIA 前判断；配置无效也暂停鼠标功能。应用排除仍是便利过滤，不是系统防泄露沙箱，不按浏览器网址区分。
- 图标不激活目标外的窗口、不显示正文、最多保留 5 秒。新选择、外部点击／滚动、Escape、前台变化、进入设置／学习本、主窗操作、停用或退出都撤销候选。点击时再次核对窗口、规则、选区内容和有效代次，再将原文填入主窗，**无论快捷键自动翻译设置为何都不自动发送**。
- 不覆盖正在进行的翻译、取词或模态编辑。主窗已显示时不提供自动鼠标图标，以免替换已有草稿；快捷键／手动粘贴继续可用。主题和界面语言只更改本地标签，不重新读取正文或请求翻译。
- 全局低级鼠标钩子回调仅筛选按钮／滚轮事件、快照坐标和窗口标识并有界排队；移动事件不发工作、不读取进程名／正文／文件。忽略并撤销注入事件。UIA 在后台执行，与快捷键共用单工作者占用保护；超时不生成无界线程或自动重试。前台事件只用于撤销；定时检查只在候选处理中或图标可见时运行。

## 窗口生命周期修复与反例

本轮完整回归发现 L1 和验收入口将每次 `Loaded` 当成初始化／开始验收。新增显式重复 `Loaded` 用例在旧实现实际失败（`repeated-loaded-before.log`、`qualified-ui/run-1-f1fdde5b3f8f417da819a2c392860d51/`），改为单次处理。另一个确定的结构问题是学习本 `Loading` 任务包含嵌套编辑器 `ShowDialog`，编辑器打开时父初始化仍未完成；新增断言实际失败（`modal-parent-before.log`），现改为先加载完毕，再在 Dispatcher 空闲队列打开编辑器。取消按钮有显式 Close 路径，仍保留原来保存中取消的保护；验收改为等待编辑器真实关闭再关闭 owner，不以固定 30ms 等待假定关闭已完成。

隐藏启动的模态超时轮次保留于 `stage2-ui-sealed/`、`qualified-ui/` 和 `loaded-final-default.log` 等。对自有测试进程的线程栈及临时内存事件记录显示：测试回调／owner 关闭已经完成，而 UI 仍在内层 ShowDialog 帧等待（`qualified-ui/run-2-5148f65ae6de45fcb20be3fef9c095bf/`）；不是磁盘性能或 HTTP 超时。公开 WPF Window 源码只用作理解嵌套 modal frame（本地参考 `artifacts/references/wpf-window-q2/`），未复制框架源码。修复后隐藏启动两轮与默认／原生整组通过；不据此保证所有桌面焦点条件永无故障。

新增鼠标验收曾泄漏会话学习检查开关，使旧重试用例失败；已恢复原开关。旧交互验收还在主窗刚 Show 时同步断言子控件 IsVisible，报告确认逻辑状态是 Visible、父窗可见，但有效子可见性尚未重新连接；现等待 Loaded 队列并 UpdateLayout，再保留原 IsVisible 断言。托盘键盘焦点仍有一轮因桌面环境失败（`q2-post-modal.log`）；未放宽断言。临时模态诊断代码和独立诊断脚本不进入产品。

点击接线采用共享 session，不在测试中手写另一条成功路径；删除 `input.Flush()` 的隔离替代源码构建实际触发“合法点击被拒绝”断言（`stage2-mutation.log`、`stage2-ui-mutant/`），正常源码未被改坏。Flush 只清算已到达的按钮事件：图标 down/up 保留候选，队列中的外部点击会在复核前撤销，不允许旧文本绕过新事件。
