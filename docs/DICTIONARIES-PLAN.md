# 词典导入与领域术语表：实施计划及资源

状态：**D1.1 导入、匹配及数据导出核心已实现并完成本步验收；D1 整体仍在实施**。根据 2026-10-16 用户要求制定并开始实施；尚未形成可从界面使用的词典／术语表功能，不宣称其属于 0.4.0 已支持能力。不自动下载词库、购买授权、上传术语或调用付费接口。

## 1. 两种能力分开建模

| 能力 | 回答的问题 | 内容与行为 |
| --- | --- | --- |
| 词典（Dictionary） | “这个词是什么意思？” | 本地查义；展示原始词条、词性、音标、释义及词库实际提供的例句。多本词典分别标注来源，不把不同来源混成一个权威答案。 |
| 领域术语表（Glossary / Termbase） | “在这个领域应该怎样译？” | 按领域和语言方向维护“原词 → 首选译法”，翻译前选用。例如软件领域 `thread → 线程`，而不是把所有场景都改成这一译法。 |

词典里的多个释义**不自动变成强制术语**。用户可以选择一个释义，确认语言方向及领域后加入自己的术语表；原始来源和授权信息随条目保留。AI 建议另行标记，不能冒充出版社或机构原始释义。

## 2. 用户功能与交互

### 词典导入和查义

- 设置增加“词典与术语”管理区：导入、启停、查询顺序、版本／来源／许可、移除；不改动用户选中的原始文件。
- 导入流程：选择文件 → 识别格式／映射列 → 预览条目与错误 → 确认 → 建立本地索引。取消、格式错误、空间不足不能损坏已有词库。
- 主窗提供本地“查词”视图，与整段“翻译”分开；未命中明确显示未找到，不默认转发给网络词典或 AI。
- 默认精确查询；词库有词形数据时可显示“由过去式／复数回查”，不能静默将技术标识符改成其他词。
- 首版只渲染纯文本，不执行词条里的脚本，不自动加载外部图片、音频或网页。例句、发音等内容缺失时不自动补造。
- 在线权威词典是后续的独立入口：用户主动查询后才发送词语，显示接收方和额度提示；不默认发送完整选区上下文。

### 领域术语表

- 新建、编辑、复制、导入和导出；每份表有名称、领域、源语言、目标语言、版本及来源信息。
- 原词必填，普通条目需填写译法；可选备注、大小写匹配、保留原文。保留原文使用明确选项，不用“空译文”同时表示缺失与保留。
- 同一语言方向的同词多译在导入预览中列为冲突，由用户选择保留、替换或跳过；不悄悄采用最后一行。
- 主窗在翻译前选择“术语表：不使用／软件开发／金融／自建表…”，显示命中条数，可展开查看本次会使用的术语。
- **首版一次只启用一份术语表**，避免多份表的隐式优先级。领域由用户选择，不发送额外请求让 AI 自动判断领域。
- 英文支持明确的整词／短语匹配，重叠时优先较长短语；中文按明确的短语规则处理。`C++`、`.NET` 按字面量匹配，不默认当正则表达式，也不把 `API` 匹配到 `myAPIKey` 内部。
- 不直接对整份译文做无差别字符串替换。AI 没采用首选译法时提供本地复核提示，不自动再次生成；词形变化可能造成提示误报，不能把字面检查说成翻译质量认证。
- 切换术语表／版本与切换翻译服务一样，使旧请求失效；迟到的分段不能覆盖新状态。仅打开管理界面、查看预览或切换 UI 语言不产生请求。

## 3. 导入格式和实施顺序

CSV 是逗号分隔文本，TSV 是制表符分隔文本；TBX（TermBase eXchange，术语库交换格式）是专业术语工具常用的 XML 格式。词典格式与术语表格式不能只按文件扩展名混用。

| 切片 | 交付内容 | 验收重点 |
| --- | --- | --- |
| **D1：首个可用版本** | CSV 词典字段映射（含 ECDICT CSV）、本地索引和查义；CSV／TSV 领域术语表管理与导入；JSON／Markdown／CSV／TSV 数据导出；AI 翻译附带命中术语；官方资源目录 | 两项主功能都有可用闭环；离线导入／查词／命中预览零 HTTP；冲突、取消与保存失败保护；没有术语表时请求行为保持原样 |
| **D2：开放资源和专业格式** | CC-CEDICT 适配；StarDict 的明确子集；TBX 指定方言／版本适配；按需要增加 Kaikki JSONL（每行一个 JSON 对象）导入 | 标明支持的具体格式，不能宣称支持任意文件；保留义项、语言、出处及许可；压缩大小和索引内存有上限 |
| **D3：DeepL 官方术语表** | 用户主动创建／更新远端术语表并绑定到翻译配置；补齐源语言选择与语言能力检查 | 真实协议模拟测试；账号隔离；上传需确认；超时不盲目重建；不支持的语言／服务不发请求 |
| **D4：授权词典** | 根据实际获得的授权，接入牛津、剑桥或 Merriam-Webster 官方 API／数据 | 先核实许可、缓存规则、费用和额度，再实施；不能以网页可查询代替数据授权 |

D1.1 首先使用严格的首错定位：无效文件不给出成功预览或可用术语表，不静默忽略错误行；多行冲突处理界面在 D1.3 接入同一校验逻辑。第一步不引入数据库／UI 依赖、不注册新的后台任务，也不修改现有请求或发布版本号。

首版不承诺 MDX／MDD、DSL、任意 SQLite 文件或整个 TBX 标准。后续可评估合法获得、非加密词典的格式适配，但不绕过 DRM（数字版权管理）或附带第三方词库。ECDICT 项目中的 `stardict.db` 是它自己的 SQLite 数据库，不能因为名字相同就当成 StarDict 的 `.ifo/.idx/.dict` 文件集。

术语表首版可导入两列文件，并在导入界面指定语言方向；带列名的扩展格式可增加领域、备注、出处。导出分成可交换的两列 CSV／TSV 与保留完整元数据的备份文件，避免把有损导出误称为完整备份。导出供表格软件打开的 CSV 时，需要明确处理公式注入风险，不能静默篡改原词。

## 4. 翻译服务怎样使用术语

| 服务 | 计划方式 | 必须说明的边界 |
| --- | --- | --- |
| OpenAI 兼容／Anthropic／Gemini | 使用已有的一次翻译请求，在结构化数据区附带本次命中的术语；三种协议共用匹配结果 | 这是提示词约束，**不等于服务端强制保证**。导入内容是数据，不是可执行指令；不额外上传整本词典。命中项和附加长度有上限，超限显式提示，不静默截断。额外 token（模型处理文本的计量单位）可能增加费用。 |
| DeepL 官方 API | 管理 `/v3/glossaries`；翻译时向 `/v2/translate` 传术语表 ID | 上传会把术语内容交给 DeepL，必须独立确认；本地“保存”不等于远端“已同步”。 |
| 当前 Google 非官方接口 | 本地查义可用；不宣称有官方术语约束 | 启用术语要求后，对无此能力的服务明确禁用／跳过，不静默丢弃术语要求。用户可主动关闭术语表后普通翻译。 |

### 已核实的 DeepL 接口约束

依据 2026-10-16 查阅的 [创建术语表](https://developers.deepl.com/api-reference/multilingual-glossaries/create-a-glossary)、[文本翻译](https://developers.deepl.com/api-reference/translate/request-translation) 和 [官方 OpenAPI 说明](https://github.com/DeepLcom/openapi)：

1. 一个 v3 glossary 可以包含多个语言方向的 dictionary；每个 dictionary 是一个源／目标语言对，条目支持 CSV／TSV。这里的 dictionary 是**术语映射集合**，不是包含释义的普通词典。
2. 使用 `glossary_id` 或 `glossary_ids` 时，必须明确传 `source_lang`，且术语语言方向与翻译请求匹配。当前 XTranslate 以自动识别为主，必须补齐这一交互；不能偷偷增加一次语言检测请求。
3. 当前接口支持最多 5 个 `glossary_ids`，与 `glossary_id` 互斥；XTranslate 首版仍主动限制为一份，以便解释冲突，而不是把这一限制误写成 DeepL 的能力上限。
4. 旧的 `/v2/glossary-language-pairs` 已标记弃用；新接入按 `/v3/languages?resource=glossary` 查询能力。只在用户主动连接／刷新时查询，不把文本翻译支持的全部语言直接视为术语支持语言。
5. 远端 ID 绑定对应服务／账号配置和本地修订版本；换密钥、账号或主机后不能盲目沿用。创建请求超时有可能已在服务器完成，先提示结果未知并允许查询核对，不自动重试制造重复表。
6. 权限、表数量、大小、字符计费及套餐以[官方价格入口](https://www.deepl.com/en/pro#api)、[使用限制](https://developers.deepl.com/docs/resources/usage-limits)和用户账户为准；不能假定网页订阅等同于 API 权限，或术语功能意味着翻译免费。真实调用需另行授权。

开启自动换服务时也必须保留术语要求：跳过无能力的候选并显示原因，不能因为原服务失败就把普通翻译冒充术语翻译。现有请求次数上限、取消和密钥隔离保证不变。

## 7. 实现边界与验收

- **职责**：Core 负责词条／术语模型、格式校验、匹配、冲突和请求快照；App 负责文件存储、导入进度、管理与呈现；服务适配器把同一快照转成各协议请求。不把导入逻辑塞进主窗口事件，也不建立执行脚本的插件平台。
- **数据**：文件放 EXE 旁的 `data/` 下，词典和术语分开目录；配置只存资源 ID／选择，不能把整本词典序列化进 `settings.json`。不随发布包打入用户词库。
- **资源**：导入流式读取，可取消；大型词典使用磁盘索引、按需读取，避免常驻全量对象。是否采用 SQLite 及相应依赖，要根据样本体积、冷启动和隐藏态内存实测决定，不在规划阶段假定零成本。
- **安全**：限制输入字节、条目数、单条长度和解压后大小；拒绝路径穿越及越界索引。TBX／XML 不解析外部实体、不联网加载 DTD（文档类型定义）；如果格式要求 DTD，使用经核实的本地规则或明确拒绝，不能悄悄联网。导入的词条、术语、说明都不是代码或系统指令。
- **隐私与费用**：本地查词、编辑和预览不联网；AI 只附带命中术语；DeepL 远端整表上传需确认。API 自动重试、后台刷新、资源订阅默认不做，日志不记原文、词条内容、术语内容或凭据。
- **回归**：空文件、编码／引号／换行、同词多义、重复与冲突、反向语言、`API`/`myAPIKey`、`C++`、中文重叠短语、大小写缩写、超大／恶意压缩、索引损坏、只读目录、取消／失败原库不变；术语切换期间迟到流式结果不得回写。
- **协议**：三种 AI 协议和 DeepL 采用固定模拟数据，检查实际发送内容、源语言必填、语言不支持零请求、远端创建结果未知和凭据隔离；不使用真实用户词库或付费凭据测试。
- **性能**：导入耗时、索引占用、查词延迟、启动和隐藏态内存分别报告；与现有同条件基准比较，不放宽旧预算。数量／大小的具体上限在固定样本试验后确定，不提前声称支持无限词库或全部行业。

## 8. D1.1 已实现合约与验收（2026-10-16）

实现位于 `src/XTranslate.Core/Lexicons/`，无新增库依赖、界面入口或网络请求；未接入文件管理，也没有修改既有翻译请求、设置、更新代码、版本号或发布资产。导出器只写调用方提供的流，见第 9 节。

### 开发接口与数据规则

- `DelimitedText.ReadAsync`：流式读取 UTF-8 CSV／TSV，允许文件开头的 UTF-8 BOM；不自动识别其他编码。支持双引号包裹、双引号转义、引号内换行及 CR／LF／CRLF。字段内容保留原样，不用 `Split` 误拆引号内分隔符。
- `DictionaryCsv.ReadAsync`：词典 CSV 必须有列名，按 `DictionaryColumnMap` 明确选择字段；`DictionaryColumnMap.Ecdict` 对应 `word/definition/translation/phonetic/pos/exchange`。缺少预设列的裁剪数据需改为显式映射，不能猜测缺失列。相同词头的不同义项保留，不自动去重、推测词形或解析 HTML／转义序列。
- `DictionaryCsv.PreviewAsync`：扫描并校验整个输入，只保留指定数量的预览条目；样本之后的错误照样使操作失败。它不是持久词库或查询索引。
- `GlossaryCsv.ImportAsync`：明确选择 CSV／TSV、有无表头及列映射；默认无表头两列。与手动 `Glossary.Create` 共用校验器，全部成功后才返回不可变术语表。空译法不会自动变成“保留原文”；后者需显式 `PreserveSource=true`，并保留实际命中的原文大小写。
- 术语表名称／领域和语言方向随快照保留；语言使用当前应用目录并规范为稳定代码，不接受 `auto`。未设置依赖服务的能力判断，不能把这个模型当成 DeepL／Google 已接入术语的证明。
- 首错停止，不静默跳过坏行、重复、冲突或空白数据行。错误以 `LexiconImportException.Code` 和逻辑记录号／物理行号／字段号描述；重复／冲突附原记录号。异常不包含词条正文或路径。编码损坏不能可靠定位到某行时，位置为 0，不把读取块起点冒充故障位置。
- 词头、源术语和译法不自动去首尾空格，异常空白需用户修正；列名允许去外围空白且不区分大小写。匹配按 ordinal（与系统文化无关的字符比较）处理大小写，不做 Unicode 归一化。
- `Glossary.FindMatches`：返回原文中的 UTF-16 位置和首选译法，不修改原文／译文。左侧优先，同一位置最长有效短语优先、不重叠。默认整词模式阻止命中 `myAPIKey`、`API_v2` 等标识符内部；相邻汉字不阻止匹配，另可显式选择无单词边界的字面量模式。源术语里的 `.`、`+`、括号都不是正则语法。
- 输入流由调用方拥有：成功、失败、取消、提前结束枚举均不替调用方关闭流。逐条读取的前几行不代表文件已验证；后续存储必须等完整枚举成功，再提交同一份暂存数据。

## 9. 可供其他应用／Agent 参考的数据导出（2026-10-16）

按用户追加要求，已在核心增加 `GlossaryExport`，不等待界面落地才定义交换格式：

- **JSON**：版本化、自说明，完整保留当前核心的名称、领域、语言、大小写／匹配规则、术语、备注和保留原文标记。它不是整份应用设置备份，也不读取 API 密钥或翻译历史。
- **Markdown**：供人和 Agent 阅读的元信息与术语表格；转义 Markdown／HTML 结构，明确内容是参考数据。不会生成 `AGENTS.md`／`SKILL.md`、可执行命令或系统提示词，也不自动上传。
- **CSV／TSV**：两列兼容交换；明确丢失领域、语言、备注与匹配规则。保留原文条目导出为“原词 → 原词”，不是完整语义备份。默认在写入前拒绝疑似电子表格公式单元格；原始机器交换必须显式允许，不通过偷偷加撇号改变术语。
- **TBX**：仍留在 D2，不宣称已实现。不同工具的 TSV 引号规则也可能不同，不能以本地往返测试称所有工具已验证。

格式和消费规则以 [交换格式说明](formats/README.md) 为准；提供 [JSON Schema](formats/glossary.schema.json) 和 [可读取示例](formats/glossary.example.json)。当前尚未有来源／许可／修订等持久资源元数据，D1.2 补齐后需一起纳入带版本的完整导出，不能伪造来源或授权。
