Q1 边界：这是取词触发器的便利过滤，**不是系统级防泄露沙箱**。同名 EXE 均被排除，不支持路径／通配符／按浏览器网站区分；已有手动输入或先前请求不因在排除应用按快捷键而被清空或取消。全局快捷键仍已注册，不承诺将这次按键透传给目标应用。配置非空时无法确认目标进程就拒绝取词，避免未知身份绕过排除。Q2／Q3 将共用同一策略；涉及外部 OCR、语言包安装、朗读下载或付费工具须另行授权。

### Q1 实现与阶段验收

入口：「设置 → 通用 → 不取词的应用」。每行一个文件名，可省略末尾 `.exe`；去外围空白，忽略空行，去重并统一保存为小写带 `.exe`。不支持路径、通配符、正则；最多 128 个非空输入行／文件名 255 UTF-16 字符，超限整表拒绝而非部分采用。核心 `CaptureAppPolicy` 不依赖 Windows；App 只在触发且名单非空时读取前台窗口所属进程名，不记录路径／标题／正文，也不扫描整个进程列表。

规则在 `CaptureSelectionAsync` 进入选区读取前判断，拒绝时不唤出窗口、不清空原文／结果、不取消已有无关请求；设置和学习本打开期间仍不响应取词。已保存的名单在加载时无效，则保留原规则并暂停快捷键；整个配置无法解析时，原文件不改写，使用禁用取词的临时配置和明显无效的 `<invalid configuration>` 占位，需用户明确修正／清空后保存。旧版没有此字段时保持空名单与原行为；本步不引入默认排除应用。

实际检查：Core **135/135**（新增 4 组：精确匹配／双后缀／Unicode、未知目标、整表失败与上限、土耳其文化及不可变快照）；存储 **44/44**、Diagnostics **10/10**；隔离 Release 构建 `-warnaserror` **零警告／错误**；真实 WPF 模拟 **81/81**，新增 5 组应用排除记录。证据 `artifacts/verification/capture-exclusions-20261021/sealed-checks.log`、`ui-sealed/run-20261021-001103-53570b87/ui-smoke.json`；存储／Diagnostics 记录在同目录 `final-checks.log`。最终追加重复字段及根 null 配置拒绝，首轮和最后一轮同为 81/81，未降低断言。已实际查看中文浅色、英文深色的最小设置截图。

WPF 覆盖真实设置保存／重开／取消、语言切换不改草稿、无效路径定位字段且零写入、锁定文件失败保留草稿／旧规则；通过替换 OS 身份与文本读取边界验证实际取词编排：命中／未知／非法配置在读正文前停止，窗口不出现、输入及无关请求不变；允许项／空名单仍可到达模拟取词边界。调用真实 Win32 读取本次测试窗口的进程名，不读取其他应用正文或用户剪贴板。配置根 null、字段 null、错类型、重复字段、非法名单及损坏 JSON 均拒绝自动取词、不改原文件。以上操作 **零模拟 HTTP**；单独验证手动翻译仍恰好发送 **1 次固定模拟请求**，不是宣称所有翻译零网络。

## 具体边界

- 软件语言：跟随系统 / 简体中文 / English。只改变界面标签、状态、错误、设置和托盘菜单，不更改原文、译文、目标语言或翻译服务，不触发新请求。
- 临时弹窗：从快捷键取词进入；失焦收起由设置控制，固定时保持可见；进入设置窗口或使用下拉选择时不能误收起。
- 手动窗口：从应用启动或托盘进入，失焦仍保持窗口。
- 翻译中：明确显示请求状态；取消不会改用别的服务，迟到结果不能覆盖新的输入或重新弹出窗口。
- 本轮不增加输入即自动发送、自动复制或自动替换原文，避免额外网络请求与剪贴板写入。

## 验收要求

双语标签键集合完整；语言保存与重启生效；中英文主窗/设置截图；无原文时不可翻译；清空使旧请求失效；复制与聚焦快捷键；固定/失焦/设置弹窗边界；保留原有取消、来源与数据保护测试。

性能测量使用固定测试文本和模拟翻译，不调用付费 API、不读取用户剪贴板；资源数据与本地 UI 周期延迟单独报告，网络耗时不得混为 UI 性能。

## 0.2.1 后续开发：AI 流式译文

### 起点与范围

- 开发起点：本地 `main` 与刷新后的 `origin/main` 同为 `9443140`（`v0.2.1`），无本地改动或分叉。
- 基线已运行：Core 17/17、Release 构建 0 warnings / 0 errors、WPF smoke 21/21；证据：`artifacts/verification/ai-streaming-baseline/run-20261013-110525-10c0cd4e/ui-smoke.json`。
- 本阶段改进 AI 翻译等待体验，不宣称完整对标 QTranslate；更早口头讨论的其他效果没有完整仓库记录，不视为已确认规格。
- 只增加可选的真实流式输出（边生成边显示），默认关闭以保留已有服务的兼容性。采用 Server-Sent Events（SSE，服务器推送事件）读取 OpenAI 兼容 Chat Completions 的增量内容，不添加逐字动画、自动请求、重试或跨服务回退。
- 不包含 OCR、翻译历史、并行比较、质量检查，也不更改已发布的 0.2.1 产物。

### 实现边界与验收标准

1. Core：发送单次流式请求，正确处理分帧 UTF-8、多行事件、完成标记和模型来源；约束响应大小，20 秒总超时与取消覆盖整个读取过程。截断、拒绝或协议错误不得当成成功译文。
2. 界面：新增双语设置并持久化；约 50ms 合并一次增量更新，只在请求中使用计时器；生成中明确标记未完成，整份译文复制入口仅在成功后启用。
3. 生命周期：取消、编辑、切换服务/目标语言、设置或隐藏窗口时停止预览并清除半成品；迟到分段和旧请求结束不能污染新请求。切换界面语言不打断流式请求、不增加 HTTP。
4. 验证：本地模拟 HTTP 的 Core 边界测试、真实 WPF 设置和流式生命周期 smoke、Release 构建、截图检查；不使用真实凭据、用户原文或剪贴板。不把本轮短测当成新的 8 小时内存验收。

流式协议要求响应类型为 `text/event-stream`，单个 completion 的 `index` 为 0，且同时收到 `finish_reason: "stop"` 和完整的 `[DONE]` 事件才确认成功。角色、推理内容、心跳和用量信息不会混入译文；工具调用、拒绝、截断或连接结束不冒充完整结果。不支持该协议的接口可由用户关闭流式选项后手动重试，不做自动降级。

本地读取限制按解码后的 UTF-16 代码单元（.NET `char` 的计数单位）计算：译文最多 50,000，单行/单事件最多 65,536，整个响应最多 2,097,152。限制在读取过程中生效，不先缓存整个响应或无限长行。这些是客户端内存保护，不是服务端计费额度；取消也不保证服务端立即停止生成或计费。
