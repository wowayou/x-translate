Q1 边界：这是取词触发器的便利过滤，**不是系统级防泄露沙箱**。同名 EXE 均被排除，不支持路径／通配符／按浏览器网站区分；已有手动输入或先前请求不因在排除应用按快捷键而被清空或取消。全局快捷键仍已注册，不承诺将这次按键透传给目标应用。配置非空时无法确认目标进程就拒绝取词，避免未知身份绕过排除。Q2／Q3 将共用同一策略；涉及外部 OCR、语言包安装、朗读下载或付费工具须另行授权。

### Q1 实现与阶段验收

入口：「设置 → 通用 → 不取词的应用」。每行一个文件名，可省略末尾 `.exe`；去外围空白，忽略空行，去重并统一保存为小写带 `.exe`。不支持路径、通配符、正则；最多 128 个非空输入行／文件名 255 UTF-16 字符，超限整表拒绝而非部分采用。核心 `CaptureAppPolicy` 不依赖 Windows；App 只在触发且名单非空时读取前台窗口所属进程名，不记录路径／标题／正文，也不扫描整个进程列表。

规则在 `CaptureSelectionAsync` 进入选区读取前判断，拒绝时不唤出窗口、不清空原文／结果、不取消已有无关请求；设置和学习本打开期间仍不响应取词。已保存的名单在加载时无效，则保留原规则并暂停快捷键；整个配置无法解析时，原文件不改写，使用禁用取词的临时配置和明显无效的 `<invalid configuration>` 占位，需用户明确修正／清空后保存。旧版没有此字段时保持空名单与原行为；本步不引入默认排除应用。

实际检查：Core **135/135**（新增 4 组：精确匹配／双后缀／Unicode、未知目标、整表失败与上限、土耳其文化及不可变快照）；存储 **44/44**、Diagnostics **10/10**；隔离 Release 构建 `-warnaserror` **零警告／错误**；真实 WPF 模拟 **81/81**，新增 5 组应用排除记录。证据 `artifacts/verification/capture-exclusions-20261021/sealed-checks.log`、`ui-sealed/run-20261021-001103-53570b87/ui-smoke.json`；存储／Diagnostics 记录在同目录 `final-checks.log`。最终追加重复字段及根 null 配置拒绝，首轮和最后一轮同为 81/81，未降低断言。已实际查看中文浅色、英文深色的最小设置截图。

WPF 覆盖真实设置保存／重开／取消、语言切换不改草稿、无效路径定位字段且零写入、锁定文件失败保留草稿／旧规则；通过替换 OS 身份与文本读取边界验证实际取词编排：命中／未知／非法配置在读正文前停止，窗口不出现、输入及无关请求不变；允许项／空名单仍可到达模拟取词边界。调用真实 Win32 读取本次测试窗口的进程名，不读取其他应用正文或用户剪贴板。配置根 null、字段 null、错类型、重复字段、非法名单及损坏 JSON 均拒绝自动取词、不改原文件。以上操作 **零模拟 HTTP**；单独验证手动翻译仍恰好发送 **1 次固定模拟请求**，不是宣称所有翻译零网络。

当时未验证：真实第三方软件的完整快捷键／选区链路、管理员软件、长时性能和发布包；Q2 鼠标图标及 Q3 OCR 均未实施。后续 Q2 已完成独立阶段，不能将本段 Q1 模拟用例或既有 Ctrl+Q 称作 Q2 真人链路验收。本轮 Q1 无真实翻译／OCR 网络请求、安装／更新、语言包下载或发布；L1 和 D1.2 的独立验收不因此扩张为整个学习／词典系统完成。

### 借鉴 REA：证据驱动的有限行为重建

根据用户追加参考，阅读 [REA（Reverse Engineer Anything，面向 Agent 的逆向调查工具）](https://github.com/morluto/rea)；本轮文档固定到提交 [`9258df02cc414112d4fa91a425f0d599f43e2357`](https://github.com/morluto/rea/tree/9258df02cc414112d4fa91a425f0d599f43e2357)。重点为 [桌面目录的事实与不确定性](https://github.com/morluto/rea/blob/9258df02cc414112d4fa91a425f0d599f43e2357/docs/desktop-applications.md)、[调查／重建验证／未知项审计流程](https://github.com/morluto/rea/blob/9258df02cc414112d4fa91a425f0d599f43e2357/docs/mcp-prompts.md)、[证据保存与退出状态](https://github.com/morluto/rea/blob/9258df02cc414112d4fa91a425f0d599f43e2357/docs/cli.md)、`testing.md` 的测试深度和端到端边界章节，以及 MIT 许可／免责声明。原文与 SHA-256 清单仅保存在忽略的 `artifacts/references/rea-20261021/`，未安装 REA、注册 MCP、下载分析引擎或运行其代码。

采用它的方法，不移植完整调查平台，也不把工具许可当成目标软件许可：

1. **先定对象和问题**：记录本机 QTranslate 的具体版本及少量相关文件身份；只读的 4 文件完整哈希见 `artifacts/references/qtranslate-6.10-20261021/identity.json`，不是全目录快照。先问“选区何时读取、何时发送、如何取消、排除应用是否阻止读取”，不先搜一堆实现或复制外观。
2. **分开事实／推断／未知**：帮助中存在功能只证明有相应描述，不能证明引擎、实际联网或边界语义；实验只覆盖其有限输入。当前没有运行 QTranslate，因此**不存在已通过的 QTranslate ↔ XTranslate 运行行为等价结论**。
3. **先写有限规格，再独立实现**：下面的验收是 XTranslate 的产品选择，不冒充对 QTranslate 内部的还原。对实际确证的输入输出才作逐项对照，未知项保留，不自动猜测或换技术／服务掩盖失败。
4. **证据匹配声明深度**：核心单元测试证明规则；替换 OS／服务边界的真实 WPF 流程证明接线与生命周期；本机真实引擎实验只证明该引擎的固定样本。模拟通过不等于真实第三方应用通过；异常、取消、清理、陈旧输入和容量检查不能因“界面像了”而删去。
5. **有界、可重放、保留反例**：固定样本、明确语言／目标／版本、限额／超时、来源哈希、新输出目录；既查退出码也查本次报告的成功字段。保留失败轮次，不把返回 0、预览无内容或工具不可用解释为所有能力已验证。

#### Q3 的首个实验：真实本地引擎、合成图片（不是 OCR 交付）

新增 [手动可运行探针](../tools/ocr/README.md) `tools/ocr/Probe-WindowsOcr.ps1`，在新目录生成 `960×160` 固定英文图片，不读取用户图片／屏幕／剪贴板；最多 2 次本地识别，单次异步等候 5s、累计 30s 检查，本轮外层自有进程硬超时 45s；没有脚本 HTTP、云接口、自动重试或语言包安装。

本机 Win11 build 26200、Windows PowerShell 5.1.26100.8457：系统列出 en-US／ja／zh-Hans-CN，最大维度 10000。最终 `artifacts/verification/ocr-local-20261021/sealed/ocr-probe.json`：明确选用 en-US，两次均精确输出 `HELLO WORLD 123`（16.6ms／4.2ms）；明确不支持的 `zxx` 返回无引擎，未改用用户语言。图片 SHA-256 `b268f3556714989a57b0bd5180671df222a9f869e2483e61f758e3f47ac6b517`，已查看生成图片。耗时仅该简单样本，不是屏幕识别或 UI 延迟预算。

首轮实际失败：宿主未提供 `Get-FileHash` 命令，报告保留于 `first/`；未据父进程返回成功宣称识别通过。改用 .NET 自带 SHA-256 后重新执行并同时核对真实退出码与新报告。另测已有证据目录，退出码 **1**、图片和报告字节均不变（`existing-directory-check.json`）。未测超时／异步取消、缺失 en-US 的真实系统、.NET 10 投影、复杂图片或系统网络遥测；脚本不调用网络不等于已经抓包证明整个 Windows 零网络。

这个实验仅关闭“本机 Windows 引擎能否在明确语言下识别受控图片”的问题；Q3 应用功能、D1.3 以后及 L2／L3 仍按各自计划实施。Q2 已另行完成本地阶段验收，不因这些阶段提交宣布整体完成。

## 具体边界

- 软件语言：跟随系统 / 简体中文 / English。只改变界面标签、状态、错误、设置和托盘菜单，不更改原文、译文、目标语言或翻译服务，不触发新请求。
- 临时弹窗：从快捷键取词进入；失焦收起由设置控制，固定时保持可见；进入设置窗口或使用下拉选择时不能误收起。
- 手动窗口：从应用启动或托盘进入，失焦仍保持窗口。
- 翻译中：明确显示请求状态；取消不会改用别的服务，迟到结果不能覆盖新的输入或重新弹出窗口。
- 本轮不增加输入即自动发送、自动复制或自动替换原文，避免额外网络请求与剪贴板写入。

## 验收要求

双语标签键集合完整；语言保存与重启生效；中英文主窗/设置截图；无原文时不可翻译；清空使旧请求失效；复制与聚焦快捷键；固定/失焦/设置弹窗边界；保留原有取消、来源与数据保护测试。

性能测量使用固定测试文本和模拟翻译，不调用付费 API、不读取用户剪贴板；资源数据与本地 UI 周期延迟单独报告，网络耗时不得混为 UI 性能。

3. 生命周期：取消、编辑、切换服务/目标语言、设置或隐藏窗口时停止预览并清除半成品；迟到分段和旧请求结束不能污染新请求。切换界面语言不打断流式请求、不增加 HTTP。

流式协议要求响应类型为 `text/event-stream`，单个 completion 的 `index` 为 0，且同时收到 `finish_reason: "stop"` 和完整的 `[DONE]` 事件才确认成功。角色、推理内容、心跳和用量信息不会混入译文；工具调用、拒绝、截断或连接结束不冒充完整结果。不支持该协议的接口可由用户关闭流式选项后手动重试，不做自动降级。

本地读取限制按解码后的 UTF-16 代码单元（.NET `char` 的计数单位）计算：译文最多 50,000，单行/单事件最多 65,536，整个响应最多 2,097,152。限制在读取过程中生效，不先缓存整个响应或无限长行。这些是客户端内存保护，不是服务端计费额度；取消也不保证服务端立即停止生成或计费。
