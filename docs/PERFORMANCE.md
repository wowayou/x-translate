# XTranslate 性能基准

性能模式只使用固定的本地测试数据，不读取用户原文、剪贴板、设置密钥或其它应用，也不会发起网络请求：

```powershell
XTranslate.exe --benchmark --benchmark-output .\benchmark-result.json
```

`--benchmark` 使用独立的 `benchmark-data` 目录和独立 mutex。窗口设置为 `ShowActivated=false`、不显示在任务栏并移到屏幕外；不会调用 `Activate`、`SetForegroundWindow` 或 `ShowForUser`。因此弹窗数据只代表离屏 WPF `Show/Hide + DispatcherPriority.Render/UpdateLayout` 的布局完成时间，不是屏幕合成时间，也不是快捷键到前台弹窗的延迟。

一次运行包含：

- 启动到首次 `ContentRendered`；启动计时从 `App` 类型加载时的 Stopwatch 开始，CLR 宿主在此之前的进程启动工作不包含在内。
- 可见 5 秒 idle、隐藏 5 秒 idle，以及 200 次本地固定 handler 翻译后的可见 5 秒恢复 idle。idle 以 200ms 间隔记录 Working Set、Private Bytes、managed heap、线程、句柄、GDI/USER 对象和进程 CPU 间隔；不执行强制 GC 或工作集清空。
- 1000 次离屏 `Show/Hide`（每次等待 Dispatcher Render 优先级和 `UpdateLayout`），以及 200 次通过 UI `TranslateNowAsync` 的固定本地 pipeline。延迟输出 p50/p90/p95/p99/max，并给出各循环前后资源差。

报告中的翻译延迟是本地 pipeline/UI 性能标签，不是网络性能。报告不会声称 OCR、8 小时 soak 或真实前台 hotkey 延迟，也不应把 `<60 MB` 之类的目标当作已达标结论。

## 独立进程 warm launch

先构建要测的发布目录，然后运行：

```powershell
.\benchmark.ps1 -ExecutablePath .\artifacts\XTranslate-0.2.0-win-x64-standalone\XTranslate.exe -Runs 5
```

脚本在每个进程创建前启动计时，并轮询该进程写入的 `ContentRendered` marker，另外保存完整 benchmark JSON。轮询间隔为 50ms，测量含轮询误差；缓存不清理，所以结果标为 warm launch 而非 cold boot。每个进程默认上限为 180 秒、允许配置 45–240 秒；从进程创建到退出均计入期限，超时后即使观察到 exit 0／成功报告也仍失败。失败立即停止，不自动重试或替换样本；清理只针对本次返回的子进程，最多一次终止与一次5秒等待。

`benchmark.ps1` 只运行明确指定的可信本地程序，拒绝网络／链接路径；有界记录顶层 EXE／DLL／runtimeconfig／deps 的 SHA-256，并在每轮后核对，包含 Lite 的实际 DLL 而非仅 apphost，不遍历 `data`。这是平铺发布目录的身份记录，不是递归或原子防篡改保证。报告还核对本次 PID／时间窗／marker、固定工作次数、三段完整 idle、数值类型／顺序／资源差值、无强制 GC／工作集清空和实际渲染／显式主题。旧版没有主题字段时只能不传 `-Theme`，不能声称验证了它不支持的选项；主题枚举大小写不敏感。

每次在新的 `session-*/benchmark-launch-summary.json` 保存不覆盖的证据，脚本输出该路径；输出根目录的同名文件只是可覆盖的最新会话副本。汇总区分 `attemptedRuns`、`completedRuns` 和 `successfulRuns`，`success` 仅表示所需进程／负载／指标验证通过，**不是“性能无回退”或内存预算通过**。`GC.GetTotalMemory(false)` 为辅助估值；负值原样保留，单列 `managedHeapEstimate.invalidSamples`／`managedHeapEstimatesComplete=false`，不补零、不当作节省、不参与验收或归因；缺失、非数及必需资源计数无效仍拒绝。工具自身的固定夹具反例用独立 PowerShell 进程运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\benchmark.Tests.ps1
```

只读诊断函数 `Get-BenchmarkReportAssessment`／`Get-BenchmarkArtifactAssessment` 可分别报告 `latencyMetricsValidated` 和 `idleSamplingComplete`，并列出未覆盖完整5秒的阶段；它们没有整体成功标记。共享验证仍检查全部进程、身份、负载、阶段时长、样本／资源及延迟字段，不因某段采样不完整而提前跳过其它错误。**默认runner及 `Assert-BenchmarkReport`／`Assert-BenchmarkArtifacts` 仍严格拒绝末次采样不足5000ms，exit1并立即停止，不自动改用分项诊断或重跑。** 显式分项分析不得把不完整idle用于内存／CPU聚合或称为完整验收；产品采样端本身未因此修复。
