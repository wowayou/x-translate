# 语言学习：原文检查与后续闭环

状态：**首个切片“原文检查＋翻译”已有主窗入口、核心合约和本地模拟验收；未发布，不代表整个学习系统完成。** 2026-10-20 根据用户确认实施。不自动安装／更新本机程序、不调用真实付费服务、不改发布版本。本计划独立于 [词典与术语表 D1](DICTIONARIES-PLAN.md) 的剩余交付。

## 1. 产品目标和分期

翻译用于解决眼前的理解问题；学习要帮助用户下一次更少依赖翻译。方向为“看懂 → 留下 → 想起 → 用出”，不以收藏数、打卡或 AI 分数冒充语言能力。

| 切片 | 范围 | 状态 |
| --- | --- | --- |
| 原文检查（本步） | 保留原文；区分问题、建议、最小修正、理解依据与译文；意思不确定先澄清 | 已实现并完成下述本地检查，真实模型语言准确性未验证 |
| L1 语境学习本与轻量复习 | 主动收藏词／短语／句型，可编辑和删减语境；本地保存、备份／删除；先回想后揭示答案，自评与简单间隔复习 | 待实施；先收尾词典安全存储和界面，不在本步增加第二份存储实现 |
| L2 按需讲解 | 句子结构、近义表达、用法辨析；每次只处理一个明确问题 | 待实施；独立确认接收方、请求范围与费用上限 |
| L3 表达训练 | 自己造句、可选纠错与改写，区分错误和风格偏好 | 待实施；听说能力另行评估 |

学习本与领域术语表分开：“想学这个表达”不等于“以后必须这样译”。不自动收集全部翻译历史或屏幕内容，不后台生成练习。

## 2. 原文检查的实际使用

1. 在主窗勾选“学习：检查原文（本次会话）”，主动选择已配置的 AI 服务。
2. 输入／取词后，手动点击“检查并翻译”或 Ctrl+Enter。勾选、编辑、切换服务／界面语言本身不发送请求。
3. 原文保持原样（含首尾空白），检查区先展示观察和理解依据；译文单独展示。建议修正不会回写输入框。
4. 遇到意思不确定的结果，显示歧义说明／待澄清问题，不展示确定译文，整份译文复制保持禁用。用户补充或修改后自行重新请求。

普通翻译保留现有提示词、协议和可选流式／回退行为；明确显示“原文未检查”，不能把没有检查结果当成原文正确。学习开关不持久保存，重启默认关闭；启用期间，即使设置了快捷键取词后自动翻译，也只取词等待手动确认。

### 检查不是自动改写

- 较明确的语法／拼写问题、用法／搭配建议、语域／风格说明、歧义分别建模，后两者不冒充语法错误。
- 提示模型尊重方言、聊天缩写、标题／省略句、引文、代码和专业标识符。优先保留原意的最小修正，不把更华丽的改写说成唯一正确答案。
- 区分按原文翻译、按建议最小修正翻译和意思不确定。任何采用的修正或假设应在理解依据中说明；缺词、否定、指代等影响意思且无法可靠判断时先澄清。
- “AI 未发现明显语言问题”必须附带非保证表述；语言检查不是事实核查或权威语法认证。

**限制**：程序能校验结构、引用是否来自原文、状态与翻译依据是否自洽，不能仅凭这些校验证明模型的语法判断正确、修正确实最小、没有漏报或真的需要澄清。本步没有使用真实 AI 样本测量这些语义能力。

## 3. 请求、隐私与费用边界

- OpenAI 兼容 Chat Completions、Anthropic Messages、Gemini generateContent 共用检查提示词和解析器。原文仅置于 user 内容区，视为不可信数据，不执行其中的指令。
- 一次明确操作最多发送 **1 次请求**，只用所选 AI；即使普通翻译已开启回退，学习检查也不自动换服务／重试。Core 和界面两层保留这一边界。
- Google／DeepL 不具备本步检查能力：明确提示、零请求，不偷偷改用 AI。将来能力扩展需要独立实现，不把普通翻译冒充检查。
- 检查与翻译在同一请求中完成，但更长的提示词和输出仍可能增加 token 费用。主窗说明接收主机和请求次数；**一次请求不等于固定金额或金额硬上限**。本次验收只用模拟 HTTP，未调用真实付费接口。取消也不能保证服务端立刻停止生成或计费。
- 本步只使用非流式响应：不展示原始检查 JSON 或半份结论；不更改服务已保存的流式偏好。结束、完成标记和结构都有效后才呈现。
- 结果以可选取纯文本显示，不解析 HTML／XAML／脚本。日志不写原文、译文、检查内容或密钥；没有新增持久学习记录、云同步、后台任务或依赖包。
- 界面语言在请求开始时决定解释使用中文或英文。请求中或完成后切换界面语言，只重标本地标签，不重发请求、不重新翻译已经生成的解释。

## 4. 实现合约

- `TranslationSettings.ReviewSource`、`SourceReviewInEnglish` 为请求级开关，`JsonIgnore`，不从 `settings.json` 恢复；进入异步工作前快照化。
- `TranslationResult.SourceReview == null` 表示“未检查”。`SourceReviewStatus` 区分未发现明显问题、有观察／建议、意思不确定；`TranslationBasis` 区分原文、最小修正和不确定。
- AI 返回严格版本 1 JSON：`version/status/issues/revisedSource/translationBasis/interpretation/translation`，每项观察包含 `kind/quote/explanation/suggestion`。拒绝多余／缺失／重复字段、未知版本或状态、空解释和不属于原文的引用；引用按 ordinal 精确比较，不静默做大小写或 Unicode 归一化。
- 最多 8 项观察；引用／建议最多 3,000 字符，单项解释 1,200，理解依据 2,000，建议修正原文 6,000，译文 20,000；沿用 3,000 字符输入、50,000 字符原始文本输出和既有响应体／超时上限。超限明确失败，不把截断内容当成功。
- 不确定状态必须有歧义观察和理解说明，译文／修正原文为空；其它状态必须有译文。按最小修正翻译必须有不同于原文的修正内容和理解依据；按原文翻译不得附带一份已应用的修正原文。
- 原文检查的合法“需要澄清”结果可以有空 `TranslationResult.Text`，调用方必须结合 `SourceReview` 判断，而不是把它当成普通空译文。无效结构报 `InvalidSourceReview`，不支持的服务报 `UnsupportedSourceReview`；不回落显示未解析文本。
- 界面实现为 `MainWindow.SourceReview.cs`；核心为 `SourceReview.cs` 和既有翻译链路中的窄接入。没有把个人学习条目混入词典模型或修改词库提交逻辑。

布局沿用 [设计规范](DESIGN-SYSTEM.md)：小窗口使用外层滚动；学习模式压缩原文区，并为检查详情及译文保留空间，避免新增信息挤掉原有编辑／译文区域。
